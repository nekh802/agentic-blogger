# 맛집 후기 → 네이버 블로그

프로젝트 루트(이 스킬이 있는 저장소)에서 `.venv/bin/python blogger.py` 를 사용한다.

## 1. 입력 확인
사용자에게서 다음을 받는다. 없으면 물어본다.
- **장소** (필수): 예) "성수동 OO갈비"
- **사진·동영상** (선택): 폴더 또는 파일 경로. 경로를 안 주면 파일 선택 창으로 고르게 한다. 동영상(.mov/.mp4/.m4v)이 섞여 있으면 글에 같이 넣는다.
- **메모** (선택): 맛, 가격, 웨이팅, 추천 메뉴 등 사진에 안 나오는 정보

## 2. 사진 정리
```bash
.venv/bin/python blogger.py prepare --place "<장소>" --photos "<경로>" --memo "<메모>"
```
- 사진 경로가 없으면 `--photos` 를 빼고 실행한다. 사용자 화면에 iCloud Drive가 열린 선택 창이 뜨므로 "선택 창에서 사진을 골라주세요"라고 안내하고, Bash `timeout` 을 600000 으로 준다.
- 사용자가 **휴대폰/폰에 있는 사진**이라고 하면 `--photos` 대신 `--phone` 을 붙여 **`run_in_background: true`** 로 실행한다.
  1. 몇 초 뒤 출력 파일을 Read 해서 `http://...` 주소를 찾는다.
  2. 사용자에게 안내: "맥 화면에 뜬 QR 코드를 휴대폰 카메라로 찍으세요(같은 Wi‑Fi). 열린 페이지에서 사진을 고르고 '맥으로 보내기'를 누르면 됩니다." 주소도 함께 알려준다.
  3. 완료 알림이 오면 출력 마지막 줄의 폴더로 다음 단계를 진행한다. 휴대폰에서 페이지가 안 열리면 같은 Wi‑Fi인지, 맥에 "Python 수신 연결 허용" 창이 떴는지 확인하게 한다.
- 사용자가 **밖에서/원격(휴대폰 Claude 앱, Remote Control)으로** 요청하거나 "iCloud에 올렸어"라고 하면 `--phone`(같은 Wi‑Fi 필요) 대신 `--icloud` 를 쓴다. 이 경우 맥 화면을 볼 수 없으니 파일 선택 창(`--photos` 생략)도 쓰지 않는다.
  - 사진이 아직 없으면 먼저 안내: "아이폰 사진 앱에서 사진 선택 → 공유 → '파일에 저장' → iCloud Drive > **블로그 사진** 폴더에 저장해 주세요. 다 올리면 알려주세요."
  - 실행하면 폴더의 사진을 가져오고 폴더를 비운다(파일 이름순 = 찍은 순서).
- HEIC(아이폰 사진)도 된다.
- 동영상은 `v01.mp4`, `v02.mp4`... 로 정리된다(회전 보정, 최대 1280px, 30fps, 소리 유지, **얼굴 모자이크**). 프레임마다 처리하므로 1분짜리 영상이면 1~2분 걸릴 수 있다. 동영상이 있으면 Bash `timeout` 을 600000 으로 준다.
- 마지막 줄에 출력된 폴더(`output/<시각>`)를 이후 단계에서 사용한다.

## 3. 사진 보기
그 폴더의 `01.jpg`, `02.jpg`, ... 를 Read 도구로 **모두** 열어 본다. 사진 번호 = 파일 번호.
동영상이 있으면(`review.json` 의 `videos`) 각 동영상의 장면 캡처 `v01-1.jpg`, `v01-2.jpg`, `v01-3.jpg`(앞·중간·뒤)를 Read 로 보고 무슨 영상인지 파악한다. 동영상 번호 = `v` 뒤 번호. 캡처 jpg는 글에 들어가지 않는다.

## 4. 후기 작성
같은 폴더의 `review.json` 을 읽고 `title`, `blocks`, `tags` 를 채워 다시 저장한다. `place`, `memo`, `photos`, `videos` 는 그대로 둔다.

```json
{
  "title": "성수동 OO갈비 | 갈빗살이 맛있는 고깃집 후기",
  "blocks": [
    {"type": "text", "text": "문단"},
    {"type": "photo", "index": 1, "caption": "사진 설명 한 줄"},
    {"type": "video", "index": 1, "caption": "동영상 제목 (40자 이내)"}
  ],
  "tags": ["성수동맛집", "성수갈비"]
}
```

작성 규칙:
- 사진에서 실제로 보이는 것(음식, 플레이팅, 분위기, 간판, 메뉴판 글자)과 메모만 근거로 쓴다.
- 가격, 영업시간, 주소, 맛의 세부처럼 사진·메모로 확인되지 않는 것은 지어내지 않는다.
- 광고/협찬으로 보이는 표현은 쓰지 않는다.
- 친근한 블로그 말투(~했어요, ~더라고요). 문단은 2~4문장으로 짧게.
- 제목은 '지역 + 가게명 + 대표메뉴 + 후기' 형태로 검색에 걸리게.
- 모든 사진과 동영상을 한 번씩 본문에 배치한다(`index` 는 1부터, 사진·동영상 번호는 따로 센다).
- 동영상 `caption` 은 네이버 동영상 제목(필수, 40자까지)으로 들어가 영상 아래에 보인다. 짧게 무슨 장면인지 쓴다. 예) "새라울 저녁 8시 비눗방울 타임".
- **본문의 첫 사진은 반드시 음식 사진**으로 한다. 네이버는 첫 사진을 대표 이미지(썸네일)로 쓰므로, 인테리어·간판 사진은 그 뒤에 둔다. 가장 잘 나온 메인 메뉴 사진을 고른다. 동영상도 첫 미디어가 되면 대표 이미지가 되므로 **동영상을 첫 사진보다 앞에 두지 않는다**.
- 태그는 10~20개, `#` 없이. (2026-10-25까지는 한글날 캠페인 필수 태그 3개가 발행 시 자동으로 앞에 붙으니 따로 넣지 않는다.)
- 네이버 지도는 발행 시 에디터의 '장소' 버튼으로 글 맨 끝에 자동 삽입되니(검색 실패 시 지도 링크로 대체) 본문에 넣지 않는다. 그래서 review.json의 place는 네이버 지도에서 검색되는 정확한 상호명(지점명 포함)으로 적는다.

## 5. 미리보기 & 확인
```bash
.venv/bin/python blogger.py preview output/<시각>
open output/<시각>/preview.html
```
원격 요청이면 `open` 은 생략한다(맥 화면을 못 봄). 사용자에게 제목과 본문 요약을 보여주고 **발행해도 되는지 묻는다**. 수정 요청이 있으면 review.json 을 고치고 미리보기를 다시 만든다.
(사용자가 처음부터 "바로 발행"이라고 했다면 이 확인은 생략한다.)

## 6. 발행
```bash
.venv/bin/python blogger.py publish output/<시각>
```
- 크롬이 열려 자동 입력된다. 완료되면 출력된 URL을 사용자에게 알려준다.
- 동영상은 네이버에 업로드 + 대표 이미지 추출까지 기다리므로(영상당 최대 15분) 동영상이 있으면 `run_in_background: true` 로 실행하고 완료 알림을 기다린다.
- 원격 요청이거나 발행 전 화면 확인이 필요하면 `--confirm` 을 붙여 `run_in_background: true` 로 실행한다. 출력에 `CONFIRM_WAIT` 가 나오면 같은 폴더의 `confirm.png`(발행 직전 에디터 화면)를 Read 로 보고 사진·동영상 수·지도·본문이 다 들어갔는지 확인해 사용자에게 알린다. 발행 승인을 받으면 `touch output/<시각>/.go`, 취소면 `.cancel`. `.go` 는 `CONFIRM_WAIT` 가 나온 **뒤에** 만들어야 한다(대기 시작 때 기존 신호 파일을 지움).
- 로그인 창이나 크롬 창이 맥에 열려 있는데 사용자가 원격이면 직접 조작할 수 없으니, 맥 앞에 있을 때 하도록 안내한다.
- "네이버 로그인이 필요합니다" 가 나오면 사용자에게 터미널에서 `.venv/bin/python blogger.py login` 을 직접 실행해 로그인하라고 안내한다(입력 대기가 있어 직접 실행해야 함).
- 자동 입력이 중간에 멈추면 스크립트가 Enter 입력을 기다리므로, 에러 내용을 사용자에게 전하고 브라우저에서 직접 마무리하도록 안내한다.
